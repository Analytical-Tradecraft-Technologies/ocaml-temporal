# v0.1.0-rc.1

This is the first release candidate of the experimental OCaml Temporal SDK
(`temporal-sdk` 0.1.0~rc.1). It is not a production-support or SemVer 1.x
compatibility promise. The [MVP v1 scope](../reference/v1-support-policy.md)
defines what this candidate covers and the evidence it requires.

## Changes

- First published version: a direct-style OCaml 5 workflow and activity SDK,
  a client, workers, and offline history replay, built on Temporal Core
  `8fe478ee179ed754614d230f39586f3edb57da71`.
- Prebuilt Rust bridge and OCaml SDK archives for OCaml 5.2.1, 5.3.0, 5.4.1
  and 5.5.1 on Linux x64/ARM64 (Debian 12/glibc), macOS ARM64 and Windows x64
  GNU/MinGW, plus an offline-buildable source archive for `opam install`.
- Live qualification against Temporal Server 1.32.0 with PostgreSQL 18.6 on
  Linux amd64 with OCaml 5.5.1 only.

## Breaking changes and migration

None: this is the first published version, so there is nothing to migrate
from. Later prereleases may change public signatures or behavior and will
describe the migration in their own notes.

## Residual limits

- **Activity callbacks** run one at a time per worker. Temporal activity
  timeouts do not interrupt an OCaml callback, so callback I/O must carry its
  own finite deadline.
- **Activity delivery repeats.** A crash, timeout or abandoned attempt is
  retried, so external side effects must be idempotent.
- **Cancellation is cooperative.** A callback observes cancellation and worker
  shutdown only at its heartbeats or by checking the shutdown flag.
  Workflow-level cooperative cancellation and cleanup are not supported.
- **Shutdown is bounded but abandons work.** `Worker.shutdown` returns within
  the grace period plus the teardown timeout; code still running is
  abandoned, not stopped, and its tasks are retried by Temporal.
- **Non-yielding workflow code** is detected and its task failed, but cannot
  be interrupted. The worker reports itself unhealthy and must be restarted
  by an external supervisor, which must also be able to force-terminate a
  stuck process.
- **Signals** admitted before workflow completion need an application-defined
  drain; the SDK does not wait for every handler.
- **Environment.** Only plaintext connections to a self-hosted server are
  qualified; TLS, mTLS, API keys and Temporal Cloud are not. Cross-version
  history compatibility, worker upgrades and rollback, sustained load, and
  live operation on platforms other than Linux amd64 are not qualified.
- Queries, updates, local and asynchronous activities, metrics, offline
  replay and in-process testing are experimental. Schedules, Nexus,
  interceptors, cron and delayed starts are not available.
